When it comes to security we normally follow best practices since the security is an ongoing process to keep up to date. We started out with our own proprietary security and encryption model, but after some time we made a strategic decision to use an existing open source tool for the job. Today for the private HIVE Collective we offer Keycloak (SSO, dynamic token, 2 factor and more) as an authentication service. Combining this with Synx Pass where the user can issue commands to the network stack at runtime allows the user (owner of the domain or service) to add, remove and alter ownership on network resources connected to his service.

Synx Pass is designed to control ownership in four layers in the stack. This has to do with the fact that there are a minimum of 4 entities that are part of a network vertical value chain. If you send data from A to B, you first encounter ISP, physical hardware provider, hosting supplier etc.. Second you will have the domain owner and the root domain administrator. Third you will have the service provider who creates and maintains the service and business logic. Fourth you will have the consumer and owner of the data at the endpoint.

SynxPass allows each of these entities control their own resources in the network. So in practice, if an end consumer buys a sensor device, he will get ownership of this sensor on the data layer. In the application layer two or more service providers can link and integrate their services and build a more complex system. The service providers can access the data layer from that specific sensor of the consumer. So even if the sensors are produced by the service provider, the actual data that the sensor is generating can be owned by a consumer. This is how the real Time Web concept is designed. The consumer goes to a local store and buys a robot. The robot is then in control of the consumer. He then found a service online (intelligence). He adds the robot to the service (grant the service provider access to data from the specific robot). The robot has now been morphed and data is being transformed by the service (robot becomes intelligent). Later the service can link to other services building more intelligence to the robot. The consumer can anytime remove the robot from the service and now the service provider doesn't have access to the robot data anymore.

The Real Time Web is a plug and play heterogeneous network for machines.

When we tested the RTW concept on AI students, It took them only 5 minutes to understand the concept before they started to develop their own services and integrate with each other using links.
